# HFSS ↔ CST 联调：腔体介质滤波器耦合矩阵对比（WP3 / WP4 / WP5a / WP5b）

## 0. 已确认的前提（2026-11-09，仓库主人答复）

- 形式：**腔体**（金属腔体内装介质谐振器）。谐振模式（TE01δ、TM 模等）以第一个样例为准。
- 阶数：**4 阶和 8 阶**两种。
- **有传输零点，也有交叉耦合。**
- 理想矩阵来源：**CST Filter Designer 3D**。可以导出 `.fil` 文件，整个理想矩阵也能读取并单独导出。
- 三家引擎在同一台机器上：CST 2024、HFSS 2024 R2、ADS 2027。

这几条直接决定了反提怎么做（§5）。有交叉耦合和传输零点时，响应一般是**非对称**的，
只能走 complex 域，所以**相位加载去除是必需步骤**。拓扑也不是简单的级联，
需要处理拓扑变换和解的多重性。

## 1. 工程流程

1. 在 **CST 2024** 的 Filter Designer 3D 中设定结构和指标，得到理想耦合矩阵 `M_ideal`，
   并导出 `.fil` 和矩阵文件。
2. **HFSS 2024 R2** 把 CST 里的同一个结构画出来并仿真。
3. 用 HFSS 的 S 参数**反提耦合矩阵** `M_hfss`。
4. 对比 `M_hfss` 和 `M_ideal`：哪些耦合偏了、偏多少、可能对应哪个物理尺寸。
5. （WP7）由 AI 编排调谐：改尺寸 → 重新仿真 → 再反提，直到对比通过。

`linkage/hfss_cst_link.py` 按 `linkage/hfss_ads_link.py` 的分阶段结构来写。
每个阶段都可以注入替身函数，方便单元测试；每个阶段的产物都写进 run 目录，并登记到 manifest。

## 3. 几何迁移（WP4）

**路线 G（通用，先做）：CST 导出 STEP/SAT，HFSS 导入。**

- CST worker 按当前参数导出 STEP，同时导出一个 sidecar JSON：每个实体的名字、材料
  （εr、tanδ、电导率）、端口的位置和类型、参考面位置。
- HFSS 侧用 `modeler.import_3d_cad` 导入，再按 sidecar 指定材料、边界、端口和扫频。
- CST 始终是几何的唯一来源。每轮调参都是：CST 改参数 → 导出 → HFSS 导入求解。
- 风险：导入后的实体和面怎么和 sidecar 对上（按实体名或包围盒匹配）；
  导入的几何在 HFSS 里不能参数化扫描。

**路线 P（参数化，后做）**：在 HFSS 里写一个同名参数的腔体滤波器模板（`models/` 插件），
用 `set_variables` 驱动。HFSS 能自己扫参，但每种拓扑都要写一个模板。

不论走哪条路线，都必须先通过 **G2 几何等价门**。

**腔体滤波器建模要点**（两条路线都适用）：

- **主对比用无耗模型**：腔壁设为理想导体（PEC），介质谐振器和支撑件的 tanδ 设为 0。
  理想矩阵本身是无耗的，上游 `coupling_matrix_extract` 也不处理损耗；用无耗模型可以把
  "损耗带来的偏差"和"耦合偏差"分开。有耗模型可选，只用来估计 Q 值（§5.2 第 8 步）。
- **端口**：同轴探针或抽头馈电 → HFSS 同轴 wave port，并去嵌到约定的参考面。
  CST 端口的参考面要和 HFSS 一致，记在 sidecar 里。
- 调谐螺钉、耦合螺钉、耦合窗、交叉耦合探针都按 CST 原样迁移。
- **扫频范围**：要覆盖全部传输零点，并在两侧留出带外区间，因为相位加载去除要用带外数据
  （§5.2 第 2 步）。频点数和带外宽度的具体建议由 WP5a 的 round-trip 标定给出，这里不拍数字。
- **网格收敛**：8 阶窄带滤波器对网格很敏感，必须通过 rfauto 现有的网格伪象门。

## 4. CST 理想矩阵的获取（WP3）

仓库主人已确认：Filter Designer 3D 能导出 `.fil` 文件，整个理想矩阵也能读取并单独导出。

1. **先拿样例，再写解析器。** 格式以样例为准，不准凭猜测写解析器。样例要求见 README §7
   第 1 条：用**专门做的示例设计**（仓库公开，不能用真实产品），4 阶、8 阶各一套，放进
   `tests/fixtures/cst/`。
2. 解析器同时支持 `.fil` 和单独导出的矩阵文件。两者都有时交叉核对，不一致就报错。
3. 解析结果统一转换成 rfauto 的约定（`cm_core` 使用的 N+2 矩阵），并在 `M_ideal.json` 里记录：
   - 原始文件中的矩阵是"N×N 加外部耦合（R1/RN 或 Qe）"，还是 N+2；
   - 归一化方式（是否按相对带宽归一化），以及 f0 和带宽；
   - 符号约定；
   - **拓扑掩码**：哪些元素非零（用一个记录在案的数值容差判断）。这就是物理拓扑，诊断时要用。
4. 如果能用 CST Python API 或 VBA 直接读出矩阵，worker 也提供 `get_ideal_coupling_matrix`，
   和文件解析结果互相核对。
5. G1：`.fil` 里有指标（阶数、回波损耗、传输零点位置）时，用 rfauto 内核独立综合 `M_ref`，
   和 `M_ideal` 在 folded 标准型下比较；没有指标时，改为比较 `M_ideal` 的理想响应和
   CST 导出的理想响应曲线。

## 5. 反提方案（重点）

### 5.1 上游现状

| 能力 | 现状 | 对我们的影响 |
|---|---|---|
| complex 域反提 `coupling_matrix_extract(domain="complex")` | Cauchy 拟合 + Cameron Y 留数；按"去旋转残差"自动区分实系数和复系数（非对称传输零点）两条路径，有复往返测试 | **主路线**。但对参考面相位污染敏感；上游只有纯时延去嵌，注释里记录了这还不够 |
| magnitude 域反提 | 只用 \|S\|，对相位污染免疫；但上游注释写明"单侧传输零点的 ±Ω 符号不可辨识" | **非对称响应不能用**，只能当 \|S\| 层面的旁证 |
| `cm_refine_lm`（`cm_diag.py`） | 以给定矩阵为初值做 LM 精修；支持有耗和外部 Q；拓扑只支持 folded / arrow | 要扩展成"按指定拓扑掩码精修" |
| `cm_extract_vf`（`cm_diag.py`） | 矢量拟合路线，拓扑 folded / arrow | 可以作为第三条路线交叉验证 |
| 拓扑约简 | 只有 transversal → folded / arrow（含交叉耦合族的自适应处理） | CST 的物理拓扑（CQ、三元组或自定义）没有现成的约简 |
| 损耗 | `coupling_matrix_extract` 按无耗处理 | 主对比用无耗仿真（§3） |
| 测试覆盖（粗查） | 带传输零点的综合用例最高见到 6 阶；8、9 阶的用例不带传输零点 | **8 阶 + 传输零点 + 交叉耦合的反提没有现成测试覆盖**，WP5a 先确认再补 |

### 5.2 本 fork 的反提流程

1. **输入**：无耗 HFSS 结果 `hfss_lossless.s2p`。
2. **相位加载去除**（新内核）：在带外对每个端口 S11、S22 的相位用"常数 + 线性项"拟合并扣除，
   S21 相应修正。这是腔体滤波器反提的常规步骤。作为确定性内核放在 `core/calc_families/`，
   并登记出处。可参考 Meng & Wu（IEEE T-MTT 2009，有耗耦合谐振器滤波器的解析诊断与调谐）、
   Macchiarella & Traina（IEEE MWCL 2006，适用于有耗测量数据的 Cauchy 方法）。
   **实施者核对出处后登记到 `knowledge/formula_provenance.yaml`。**
3. **complex 域 Cauchy 反提** → transversal → **folded 标准型**，得到 `M_hfss_folded`。
4. `M_ideal` 用同一套约简函数和同一种符号约定（`sign_mode`）化成 folded，得到 `M_ideal_folded`。
   如果传输零点数量超出 folded 型能表示的范围，按 `cm_core` 现有的自适应逻辑处理；
   处理不了就如实报错，不硬凑。
5. **G4 在 folded 标准型上判定。** 标准型下的对比是唯一确定的，和物理拓扑无关，适合作为门。
6. **物理拓扑诊断**：扩展 `cm_refine_lm`，支持 `topology="mask"`（支撑集取 `M_ideal` 的非零模式），
   以 `M_ideal` 为初值拟合 HFSS 数据，得到 `M_hfss_phys`。再把 `M_hfss_phys` 化成 folded，
   结果必须和第 3 步的 `M_hfss_folded` 一致。这是两条独立路线的交叉验证，计入 G3。
7. **解的多重性**：有些交叉耦合拓扑对同一个响应有不止一组实矩阵解。用多起点精修；
   如果找到残差相当但互不相同的解，就标记"解不唯一"，在报告里列出所有解。显示时可以选
   离 `M_ideal` 最近的那个，但必须明确标注，**不能悄悄只选一个**。
8. **有耗（可选）**：有耗仿真结果用 `cm_refine_lm(loss=True)` 估计各谐振器的 Q 值。只作参考，不参与 G4。

### 5.3 阈值标定（WP5a）

G4 的阈值不准拍脑袋，必须来自 round-trip 标定：

1. 用 4 阶、8 阶的实际拓扑和传输零点构造 M。拿到样例之前，先用 `cm_core` 合成的
   CQ、三元组等代表性拓扑。
2. 用 `coupling_matrix_response` 在计划使用的频点网格上算出理想响应。
3. 加上已知的相位加载（模拟馈线长度），再加上和求解器数值噪声同量级的噪声。
4. 跑完整的反提流程，统计 |ΔM|，得到方法本身的误差地板。
5. G4 阈值 = 误差地板 × 安全系数。结果写进 `knowledge/cm_extract_floor.yaml`，
   同时记录频点网格和噪声模型，报告中引用它。

## 6. 偏差来源诊断（报告必须包含）

| 对比 | 能说明什么 |
|---|---|
| `M_ideal` vs `M_ref` | CST 的综合结果和 rfauto 内核是否一致（规格是否理解一致） |
| round-trip 误差地板 | 反提方法本身的误差有多大 |
| `M_cst`（CST 自己仿真后反提）vs `M_ideal` | CST 中的结构本身是否已经实现了理想矩阵（这是设计问题，不是迁移问题） |
| `M_hfss` vs `M_cst` | 几何迁移和两个求解器之间的差异（**这是联调真正要看的数字**） |

`M_cst` 这一路建议在第一个样例上就做。没有它，`M_hfss` 和 `M_ideal` 的偏差就分不清是
"设计还没调好"还是"HFSS 和 CST 不一致"。

## 7. 物理映射（WP7 调谐用）

- 腔体滤波器的典型对应关系：M_ii ↔ 调谐螺钉深度或谐振器尺寸；M_i,i+1 ↔ 耦合窗宽度或
  耦合螺钉；交叉耦合 ↔ 交叉耦合窗或探针（磁耦合和电耦合的符号相反）。
- 对应关系**不由 AI 推测**：
  - 路线 G：由仓库主人写一个映射文件 `dr_filter_map.yaml`（CST 参数名 → 矩阵元素），
    放在工程目录，不进仓库。
  - 路线 P：写在 HFSS 模板的元数据里。
- WP7 用有限差分估计雅可比 ∂M/∂参数（每个参数做一次扰动仿真），然后做阻尼 Newton
  或空间映射迭代。可选：用 HFSS 本征模算两两谐振器之间的耦合，为雅可比提供初值。
- 每一步建议的尺寸都由内核计算；AI 只决定是否继续、是否调整阻尼、何时停止。
